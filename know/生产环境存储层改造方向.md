# DeepTutor 生产环境存储层改造方向

## 当前状态

DeepTutor 当前所有数据均以**本地文件**形式存储在 `data/` 目录下，不依赖任何外部数据库服务。

| 组件 | 当前实现 | 存储位置 |
|---|---|---|
| 向量索引 | FAISS / numpy pickle | `data/knowledge_bases/<kb>/vector_store/` |
| 知识图谱 | LightRAG JSON KV Store | `data/knowledge_bases/<kb>/rag_storage/` |
| 元数据 | JSON 文件 | `data/knowledge_bases/<kb>/metadata.json` |
| 用户数据 | 本地文件 | `data/user/` |

**优点**：零依赖、易部署、开发调试友好、可移植性强。

**局限**：并发安全性差、不支持水平扩展、大数据量性能瓶颈、无事务保证。

## 改造方向

### 1. 向量数据库：FAISS → Qdrant / Milvus / Weaviate

- **改造范围**：`src/services/rag/components/indexers/vector.py`、`src/services/rag/components/retrievers/dense.py`
- **收益**：支持分布式部署、持久化存储、高并发查询、动态增删
- **推荐**：Qdrant（轻量、REST API 友好）或 Milvus（大规模场景）

### 2. 知识图谱：JSON KV Store → Neo4j / ArangoDB

- **改造范围**：`src/services/rag/pipelines/raganything.py`、`src/services/rag/pipelines/lightrag.py` 及 LightRAG 配置
- **收益**：原生图查询性能提升数个量级、支持复杂图遍历、ACID 事务
- **说明**：LightRAG 本身已支持 Neo4j 后端，配置切换即可，架构已预留升级路径

### 3. 元数据管理：JSON → PostgreSQL / MySQL

- **改造范围**：`src/services/rag/service.py`（知识库元数据读写）、`src/knowledge/initializer.py`
- **收益**：事务安全、支持复杂查询和索引、多用户并发安全

### 4. 文件存储：本地磁盘 → S3 / MinIO

- **改造范围**：文档上传、图片存储（`data/knowledge_bases/<kb>/images/`、`data/knowledge_bases/<kb>/raw/`）
- **收益**：分布式访问、无限扩展、CDN 加速

### 5. 缓存层：内存 → Redis

- **改造范围**：会话管理、热数据缓存
- **收益**：多实例共享会话、降低重复计算

## 改造优先级建议

1. **P0**：向量数据库 + 知识图谱（核心 RAG 能力）
2. **P1**：元数据管理（多用户安全）
3. **P2**：文件存储 + 缓存（规模化部署）

## 备注

当前阶段先按文件存储方式了解整体逻辑实现，存储层升级时改动主要集中在 `src/services/rag/` 下的 pipeline 和 component 层，上层 API 和 Agent 逻辑基本不需要变动。
